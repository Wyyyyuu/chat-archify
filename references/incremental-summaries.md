# 增量摘要与阅读预算

这是宿主 AI 的摘要工作流，不内置付费 API 调用。Python 脚本负责归档、筛选、缓存失效和证据引用校验；宿主负责语义提炼与核查。完整原文、阅读包、模型摘要分别保存，不能混用覆盖率。

## 准备

已有自动采集回执时：

```text
python "<skill-dir>/scripts/summary_cache.py" prepare --collection "collection/collection-receipt.json" --cache "summary-cache" --out "summary-run"
```

普通对话使用 `--source conversation.json`，可重复提供。每份 JSON 包含 `source.thread_id` 或稳定 `source.conversation_id` 以及 `messages`；消息为公开的 `role: user/assistant`、`content`，可带原 `turn_id`、`message_id`、`source_item_id`、`phase`、`started_at`、`partial`、`collection_order`、`date`、`task_id`。其他导出先按原角色转换；不把推理、工具日志或未知私有字段混入。无原生 ID 时生成明确的本地编号；插入或重排这类来源可能使后续摘要失效，这是保守行为。

`--profile` 标识实际摘要模型／指令配置，修改配置时修改该值。筛选策略版本、摘要提示版本和消息内容进入缓存键。未变化轮次有有效摘要时才复用；失败／未提交摘要不会被假定完成。只按本地哈希复用，不证明远程聊天没有更新。用户要求最新历史时仍按采集工作流刷新来源；摘要缓存不能跳过覆盖检查。

原文以原始 JSON 字节保存到 `summary-cache/originals/<sha256>.json`，不会修改输入。凭据及不支持的隐藏字段在写入前拒绝。回执中的附件／未读缺口继续保留。内容变化会产生新版本；旧档案与旧摘要保留但不再作为当前结果使用。

## 提炼与回读

只读取本次 `reading-pack.md`；`plan.json` 是机器清单，不需整份送入模型。没有待处理轮次时阅读包为空，不再运行摘要。更新某个对话时，阅读包携带该对话已有的缓存结论，供检查新决定是否替代旧结论。来源删除单独列为待核对，不能静默删除原图节点。

默认保留全部合规消息正文，不以关键词判断能否省略。只有同一轮、同一角色与阶段、正文逐字完全一致的助手过程消息才合并正文；阅读包在原位置保留编号与重复引用。问题、最终回答、固定证据、截断消息和未完成轮次保守保留。不同轮次不自动合并，空格不同也不是完全重复。原文档案不删除任何合规消息。

节省主要来自已核查摘要的增量复用，不承诺首次阅读比全文更短。0.6.0 的关键词策略可能漏掉不含关键词的决定和待办，0.6.1 更换策略后旧摘要会失效；不得改写旧缓存键来冒充已复核。

重点检查决定及原因、失败及后续处理、被否定方案、未完成事项，以及本地实现／提交／推送／上线的区别。新规则取代旧规则时保留时间和证据，不能把历史待办直接当成当前待办。记录逐轮来源键、已读消息编号、发现和检查方式；重复核查时只读变化内容。只读预览或筛选边界检查不得登记为整轮语义复核。可定点读取：

```text
python "<skill-dir>/scripts/summary_cache.py" read "summary-run/plan.json" "<轮次编号>" --ref m3
```

省略 `--ref` 读取整轮。阅读包中的 m1、m2 是本地短引用，缓存同时保存原消息标识；不能冒充原应用消息 ID。

已有流程的关键证据可以通过 `--pins evidence.json` 强制保留。列表每项是 `thread_id`、`turn_id`、原正文 UTF-8 SHA-256 的 `content_sha256`。不匹配会报错，要求复核来源变更；不把关键词命中当作模块关联证据。

## 保存摘要

宿主只为待处理轮次写摘要，短摘要通常用数条要点。区分用户要求／助手报告／亲自验证；保留失败、被否定方案、未完成项和相关文件用途。引用选中的原文，重要信息缺失时先回读。示例：

```json
[
  {
    "unit_id": "<plan 中的轮次编号>",
    "key": "<plan.head.units 对应值，由脚本补入也可>",
    "kind": "model_summary",
    "points": [{"text": "用户决定暂缓发布；本地代码保留。", "refs": ["m1", "m3"]}],
    "reviewed_omitted_refs": []
  }
]
```

只把实际回读过的未选消息填入 `reviewed_omitted_refs`；它记录宿主判断，不代表机器验证语义。由脚本将短编号映射到 plan 中缓存键，不必让模型反复抄写长哈希。然后：

```text
python "<skill-dir>/scripts/summary_cache.py" accept "summary-run/plan.json" "summaries.json"
```

接收前重新校验原文、当前计划、内容键和引用；输入已变化或引用不存在时拒绝。摘要只作为有来源的辅助记录，不替换原文、来源覆盖回执或图中验证状态。摘要接受后重新 `prepare` 可确认命中。缓存是本地文件，保证本地一致性，不是提供方签名或对语义正确性的证明。

## 预算与验收

分别报告首次阅读、重复运行、新增轮次和修改旧消息的输入量；把已有结论上下文、提示词、回读和摘要输出算进去。无变化时只报告摘要阶段新增输入为零，不能声称整个 Codex 回合零消耗。tiktoken 可作为可选本地文本计数器，不是运行依赖；真实模型计数／usage 才是实际调用用量。不能把缓存费用优惠等同于 token 数减少。

验证原档案逐字节保留、全部用户问题／最终回答／指定证据进入阅读包、删除与修改正确失效，并对照完整轮次检查决定、失败、转向、未完成项。记录发现的遗漏与修正，不能用“文件齐全”代替“摘要没有遗漏”。生成 HTML 继续使用完整来源，不能用精简包覆盖已保存对话。
