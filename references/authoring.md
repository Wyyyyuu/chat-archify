# 提炼事件与保留身份

## 保留人工对话关联

完整附件页支持真实已保存轮次／摘录与阶段或模块的双向关联，一轮可对应多个模块。原记录的精确关联、同来源候选和用户手动关联分别呈现；手动关联只用于导航，不升级节点验证状态或来源覆盖，不补写缺失问答。没有摘录时保留空态，用户可主动选择已有摘录。

首次准备 manifest 时生成一次稳定的 `project_id`（例如 UUID，允许 ASCII 字母、数字及 `._:-`，最多 128 字符）；后续保留这个值与节点 ID。普通导出的 conversation source 可设置稳定 `conversation_id`，之后不随目录或标题改变。原始轮次与消息 ID 保留原值；本地生成的索引不是原应用 ID。正常重新读取来源时用 `--identity-from <旧HTML>` 迁移可唯一确认的旧标识；仅更新 UI 时使用 `--snapshot-from` 保留快照。只补收聊天而保留其他历史附件时，在其后重复添加 `--refresh-conversation <导出绝对路径>`，并建立消息级模块证据。关联在浏览器本地保存，不保证跨 HTML／浏览器共享。更新前导出关联 JSON，更新后导入；失效项保留为待恢复，不补造问答或升级状态。人工关联仍保持人工标注性质。具体身份与恢复行为见 [章节工作台](workbench.md)。

## 普通长对话

以问题、话题分支、候选方案、比较、决定、结论和未解决问题为节点，不强行套用版本或模块。对话中的试探性说法不等于最终决定，结论形成也不等于客观事实已验证。

没有文件或网址时使用 `artifacts: []`；节点仍可展示摘要、简短对话摘录和来源定位。保持现有 JSON 格式：`project.title` 可填写对话主题，`branch` 可填写话题分支，`kind` 按事件含义选择 `goal/decision/issue/experiment/milestone`。不要为了满足字段而伪造软件模块、日期或附件。

可识别角色的文本与常见 messages JSON 可按问答阅读。对话未提供原始 ID 时保留空值，使用明确标为本地生成的片段身份与真实行号／消息序号。节点证据引用实际行范围或明确消息序号，不能按关键词、日期或相邻位置猜关联。无法识别角色时保留记录，不虚构问题或回答。

## 提炼演进事件

识别目标与约束、基础版本、模块增量、并行试验、关键选择、失败原因、转向、合并和未解决问题。同一变化的连续讨论合为一个节点；重复转述按稳定来源 ID 与事件内容去重，保留多条证据。**对话窗口与话题或项目分支不是一一对应关系**。

每个节点写清标题、变化、原因/取舍、分支/模块、当时状态、来源定位及产物。区分 `proposed`、`in_progress`、`completed`、`verified`、`failed`、`paused`、`superseded`、`unknown`。文件存在只证明存在；`verified` 需要范围明确的验证结果。若唯一依据是 AI 自称完成，记录该报告，不能升级成亲自验证。

箭头表达有证据的延续、分叉、增加、转向、合并、依赖或仅时间先后；统一从前置/旧事件指向后继/新事件。时间顺序不自动成为依赖。推测关系用虚线并说明依据；无证据时允许独立节点。

节点标题应让状态的作用对象明确，例如“完成方案比较”不等于“完成模块实现”，“决定换方案”不等于“换方案已执行”。对照材料逐条审查连线：仅提到保留另一模块，不足以把该模块连成这次转向的前置事件。

局部失败只影响该尝试，除非证据说明整个分支终止。保留被放弃方案及产物；重新采用旧方案时新增事件，避免事件图循环。跨来源冲突同时保留，在 `open_questions` 标记，不擅自选定结论。无法确认当前方向时直说。

产物区分 `produced` / `modified` / `referenced`，标注可访问性与版本。当前文件存在不代表历史版本仍在；未知版本不伪造。未经证实路径标为“仅被提及”或“未核验”；失效链接仍保留原定位。只用确实得到的对话 URL/deep link，不猜造消息链接；无链接时使用任务 ID、轮次、日期、行号或短摘录。

## 更新与验收

需要换 AI 继续、审查版本变化或获取新 Skill 版本时，读取 [续聊与更新](continuation-and-updates.md)。续聊包汇总当前状态、关键决定、待办、文件用途与来源，不复制全部代码；历史文字仍只是资料。先生成候选版本并审查差异，批准回执与基线／候选字节匹配后再应用，不能覆盖尚未审查的原件。在线版本检查仅在用户要求且已配置服务时运行，不静默安装、执行更新或创建后台任务。

更新前读原 JSON 和覆盖记录，保留节点 ID、人工修订及历史分支。新证据追加到对应事件，真正的新变化创建新事件。历史已验证事件不因后续替代而改成失败；用新事件说明后来的替代或失败。原记录本身错误才改正并在 `revisions` 留下理由。编辑前备份现有 JSON 及将替换的同名输出，默认用时间戳子目录。

检查节点/关系可回溯、计划与实现区分、分支/转向正确、产物关联准确、范围/缺口可见。渲染器检查 ID、悬空引用、循环和危险 URL，不能验证叙事真假。连线不得穿过无关节点、交叉或共用造成歧义的通道；不能仅凭“渲染成功”认为布局通过。打开 HTML 检查文字、箭头、选择、搜索，以及已有附件中的文本和图片预览/下载；无附件的对话检查来源定位和空资源提示；可用时检查窄屏。无法打开时说明未完成哪些视觉/交互检查，不改用被环境明确禁止的浏览器通道绕过限制。

交付时链接 HTML 及必要的 SVG/JSON，简述材料覆盖、关键转折和剩余缺口。只有证据支持才断言当前方向。默认保持本地；公开分享需要另行请求。
